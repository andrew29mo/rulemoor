# Deployment evidence review — 2026-10-21

Scope: installed production systemd service, process failure/restart, orderly VM boot recovery, stale writers/requests and the interpretation of retained timing/memory records. This is an evidence/validation correction; the production Controller, backend and service code did not change in this review.

## Findings reproduced and corrected

1. **Package provenance could self-compare.** Setup ran its module-location query from the source checkout, so Python could resolve `rulemoor` from that checkout instead of the newly installed wheel. Matching bytes at that path did not establish installation equality. The query now uses an isolated interpreter (`-I`) with working directory `/`, requires a venv site-packages origin and exports per-module hashes checked against the immutable source manifest. The running systemd entrypoint, working directory, Python-path environment, cgroup and network namespace are also observed. No claim is made that the prior service was known to execute incorrect code; its installation-comparison evidence was insufficient.
2. **The artifact verifier accepted incomplete or impossible observations.** Before correction, removing all but the first host stage, deleting VM interval fields or setting the Agent interval to infinity still passed verification. The verifier now requires the full ordered stage sequence, no run/cleanup errors, finite measurements, raw monotonic endpoints and recomputed summaries. Four portable regressions cover numeric/clock boundaries and missing-duration presentation. Fourteen deliberate corruptions of actual completed evidence must be rejected.
3. **Boot recovery needed direct durable-state evidence before Agent startup.** The old fixture already SIGKILL-stopped the pending service and checked its journal/kernel state before VM shutdown. It now additionally reads a safe journal projection from the new boot's namespace bootstrap before the Agent starts. The pending phase, generation, old boot identity and policies must exactly match the pre-shutdown projection. A shutdown rollback would change these fields and fail the case. The bootstrap creates only the namespace/loopback and records absence of the owned table; it does not restore policy.
4. **Observations needed stronger attribution.** The former Agent timing ended after extra service/kernel inspection. The TLS endpoint is now timestamped immediately after the successful fresh probe, with baseline-verification time recorded separately. Memory samples check stable MainPID/start-time/boot and systemd invocation throughout sampling. The committed-boot sample is captured before the separate foreign-policy restart, rather than sampling that later DEGRADED invocation. Incomplete HTML reports display missing intervals as “not observed”, never an invented zero.

## Conclusions supported by current execution

The suite installs the production wheel and exact repository unit under actual systemd. The normal fixture adds only namespace/dependency and accounting configuration; the held-executor case explicitly overrides fault-hook clearing for fault injection, then removes that override before recovery. Automatic restart changes invocation/PID and increases systemd's restart count. Old executor identity is retired before a distinct newer policy is installed; releasing its hook cannot overwrite that policy.

For both process and pending-boot recovery, stale confirmation/cancel/apply requests are challenged during a newer pending change and again after commitment. Retained observations include unchanged pending state, actual kernel rules, generations and rejected request paths, rather than only PASS booleans. Committed boot recovery and refusal to overwrite foreign rules are separate cases.

Both kernel boot IDs change during the two orderly VM stop/start cycles. The pending journal remains pending until Agent startup on the new boot, which then reconstructs the baseline; the second boot reconstructs the durably committed policy. Current-source correspondence, raw observations, required stages, cleanup and exact JSON/HTML equality are re-audited. Older records remain identified as historical or superseded in attempt history.

## Limits retained

These are controlled, orderly VM restarts, not abrupt power removal. **Power-loss recovery remains untested.** Tests use a disposable network namespace and fresh loopback TLS connections, not external WAN reachability or general host boot ordering. A stopped Agent has no active timer, and its table can be absent before startup. Recorded intervals are single observations including probe/control overhead, not service-only timing or recovery upper bounds. RSS/VmHWM, service-cgroup charges and VM RAM have distinct scopes; the measurements do not establish total deployment peak memory. Arbitrary root writers, other distributions/architectures, storage power-loss durability and production qualification remain outside these results.
