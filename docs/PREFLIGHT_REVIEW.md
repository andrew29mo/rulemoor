# Agent-assisted management-preflight review — 2026-10-21

Reviewed starting commit: `1a5adf3`. Two read-only agents independently reviewed production logic and installed-service evidence before receiving a proposed diagnosis. They later rechecked known fixes. A bounded worker changed the deployment fixture/verifier; the main agent changed production startup/state modeling, regression tests and documentation, then ran the frozen-source suites. Agreement between agents is not execution evidence.

## Findings and corrections

1. **Optional admission configuration could prevent required startup recovery.** The service previously loaded the management-path file before constructing/starting the Controller. A missing or invalid file exited before reconciling a known pending change. The formal entrypoint now runs existing recovery before loading this admission configuration and before constructing the API server. Invalid configuration still prevents serving new requests. Real SQLite/Controller entrypoint regressions cover missing/null files and require baseline restoration, advanced generation and no Server construction. Guarded cancel, deadline, restart and reboot recovery also restore a baseline that would be rejected as a new candidate. The installed systemd fixture separately damages configuration during a pending change, SIGKILLs MainPID without graceful rollback, requires baseline recovery followed by failed API startup/start limiting, then repairs configuration and explicitly resets/starts the unit. This does not remove other startup dependencies such as TLS-key/storage availability.
2. **A failed TCP connect did not establish the cause.** A copied deployment artifact changed blocked probes to `ECONNREFUSED=111`; the previous verifier still accepted it. A dead listener could therefore satisfy the old evidence contract. Every fixture drop now requires a successful connect before installation, a timeout while installed, and successful fresh connection after removing only that fixture table. Listener PID/start/boot identity and liveness must remain unchanged around every probe. Refusal, missing recovery and changed listener are rejected by unit tests and artifact-corruption controls. The fixture owns only its disposable table; production diagnostics remain read-only.
3. **NEW-only input analysis omitted subsequent session traffic.** This was a narrow model, not a complete TCP reachability claim, but an ESTABLISHED-only drop could appear conflict-free even though a fresh TLS session needs subsequent ingress packets. External diagnostics now evaluate NEW and ESTABLISHED separately. Any certain modeled-state block is a conflict; uncertainty without a certain block remains risk. Formal regressions cover established drops and conditional uncertainty. This extension is tested with synthetic rulesets; the VM fixture's actual drops remain destination-port drops, not comprehensive TCP/conntrack conformance testing.

Two new production mutations skip service startup reconciliation or established-state analysis; both must fail assertions. The four added deployment evidence controls challenge refusal, missing TCP recovery, listener replacement and skipped configuration recovery. Existing stale-request/executor, fresh TLS confirmation, foreign-rule preservation and orderly VM recovery checks remain required.

## Evidence and limits

Latest source/run IDs, full test counts, raw monotonic endpoints, separate Agent/cgroup memory and measurements are in [deployment validation](DEPLOYMENT_VALIDATION.md), [operation measurements](MEASUREMENTS.md), [deployment JSON](../reviews/deployment/deployment.json), [HTML](../reviews/deployment/report.html) and [native/container evidence](../reviews/mvp/combined.json). HTML must exactly match rendering of the audited JSON. Historical attempts remain disclosed rather than relabeled as current evidence.

These are isolated, namespace-local Linux VM observations and portable tests of the same executable snapshot. They do not establish WAN/NAT/bridge reachability, IPv6 protection, compatibility with every firewall manager, uninterrupted connections, early-boot protection, arbitrary poisoned journal recovery, uninterruptible I/O or sudden power-loss recovery. No production readiness or recovery-time upper bound is claimed. The configuration-failure cases require local repair; no independent rollback agent is added.

The compiler already submits replacement rules through one `nft -f` batch. Atomic rule replacement does not preserve counters or override a newly selected policy's effects on traffic, and does not establish zero-downtime connections. Management preflight and read-only conflict diagnostics do not eliminate the unsupported IPv6 or full-path risks.
